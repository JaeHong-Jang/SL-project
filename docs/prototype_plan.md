# M3 보행부담 경로 프로토타입 구현 계획 (v2)

- 작성일: 2026-08-12
- 상태: 확정 — 구현 진행 기준 문서
- 목표: 거리 최단경로(M0)와 경사·기상·상호작용을 반영한 부담 최소경로(M3)를 같은 지도에서
  비교해, 연구모형을 실제 경로에 적용하면 무엇이 달라지는지 보여준다.

## 1. 최종 결론

권장 구조: `MapLibre GL JS + FastAPI + SciPy CSR/Dijkstra + 프레임워크 없는 JavaScript`.

`data/walking_network_edges_with_slope_google.csv`의 경사는 Google Elevation API 파생물로
재배포가 제한된다(`docs/DATA_LICENSES.md`). 프로토타입의 경로·비용·세그먼트 경사 표시는 모두
데이터 파생물이므로, 공개 가능한 버전은 OSM 보행망 + Copernicus GLO-30 고도로 경사를 재계산한
정제 산출물을 사용한다.

개발 완료 조건 두 단계:

1. **발표용 로컬 프로토타입 완료:** 두 경로 비교, 부담 분해, 400m 재분류, 대표 사례 3개,
   성능·계산 검증 통과.
2. **공개 배포 가능:** Google 파생 열 0건, 출처 표시, 베이스맵 이용정책, 공개판 수치 재검증 통과.

## 2. 확인된 프로젝트 기준 상태

### 2.1 데이터

- 보행 엣지 원본 467,556행, EPSG:5179. 경사 결측 900, 절대경사 100% 초과 30.
- 동일 `(u, v)` 병렬 엣지 쌍 4,716개(최대 4개). 프로필별 대표 엣지 선택과 `edge_id` 보존 필요.
- 노드 162,766개, `x`/`y` 결측 없음. Copernicus 고도 결측 241개.
- 노드 Copernicus 고도로 경사를 단순 재계산하면: 결측 900, 100% 초과 1,228, 유효 465,428.
  경사 중앙값 약 1.49%(Google) → 약 3.22%(Copernicus). **공개판 수치는 기존 발표 수치와
  자동으로 같다고 가정하지 않는다.**
- 현행 발표 수치(184m→212m 등)를 만든 `data/interim/walking_edge_costs.parquet`의 경사는
  `elevation_source=google`이다. `docs/DATA_LICENSES.md`에 이 실태를 반영 완료했다.
- 좌표계: 분석 EPSG:5179, 웹 표시 EPSG:4326 (`configs/default.yaml`).

### 2.2 M0~M3 계산 계약

- `alpha = 0.03`, `beta_weather = 0.03`, `beta_interaction = 0.08`, `snow_weight = 5.0`,
  비용 경사 상한 30%, 절대경사 100% 초과 제외.

## 3. 범위

### 3.1 V1 필수 기능

1. 서울 중심 MapLibre 지도 + **정류장 레이어**(버스 10,593 + 지하철 380 ≈ 11K 포인트,
   정적 GeoJSON, 줌 필터). 전역 경사망 레이어는 없다.
2. 출발지: 지도 자유 클릭. 도착지: **정류장 마커 클릭만 허용**(스냅 실패 정류장 80개는 목록에서 제외).
3. 입력점과 실제 스냅 노드를 각각 표시.
4. 맑음·흐림·비·눈 프리셋.
5. 같은 OD에 대해 M0·M3 경로 동시 계산·표시. **M3 경로는 엣지별 경사색 세그먼트로 표시.**
6. M0 거리, M3 실제 보행거리, M3 거리등가 부담 분리 표시.
7. 선택된 M3 경로의 거리·경사·기상·상호작용 기여분 표시.
8. M0 대비 M3 우회 여부·실제거리 증감 표시.
9. 400m 기준 분류와 `M0 ≤ 400m < M3` 재분류 강조 (D가 정류장이므로 판정이 항상 유의미).
10. **경로 경사 범례**(0~30%+, 초록→주황→빨강), 경로 범례, 레이어 표시/숨김.
11. 초기화, 출발·도착 교환(교환 시 O가 정류장이 되면 자유점 모드로 전환), 재계산.
12. 발표용 대표 사례 3개 즉시 불러오기.
13. 모델 계수·날씨 강도·데이터 출처·연구 한계 표시.
14. 오류·로딩·경로 없음 상태 처리.

### 4.2 입력 흐름 (상태 머신)

1. `waiting_origin`: 지도 클릭 → 출발지 저장
2. `waiting_destination`: **정류장 마커 클릭** → 도착지 저장 (일반 지면 클릭은 무시하고 안내 토스트)
3. `ready` → 4. `loading`(중복 요청 차단) → 5. `displayed` → 6. `error`(스냅 실패/경로 없음/서버 오류 구분)

- 지도 재클릭으로 임의 덮어쓰기 금지. 출발지/도착지 편집 버튼 후 해당 점만 재선택.
- `displayed` 상태는 **직전 날씨의 결과를 보관**한다. 날씨 변경 시 새 결과와 비교해
  "날씨로 경로가 바뀌었습니다" 표시를 만든다(대표 사례 2의 근거).

### 4.3 날씨 프리셋

| 버튼 | rain_mm | snow_cm | 비고 |
|---|---:|---:|---|
| 맑음 | 0 | 0 | M3 = M1과 동일 |
| 흐림 | 0 | 0 | 아이콘만 다름. `강수·적설이 없어 맑음과 부담 동일` 표시 |
| 비 | 2 | 0 | **기존 M3 기준선(rain_mm=2)과 정렬** — `build_e_sensitivity_runner.py`, `build_m4_senior_runner.py`, `senior_cost.py`에서 확인 |
| 눈 | 0 | 1 | **신규 시나리오 값** (적설 1cm × snow_weight 5 = 기상강도 5). 기존 기준선 아님 |

임의 강수량 입력은 V1 제외.

### 4.4 지도 표현

- M0: `거리 최단경로`, 회색 점선 + 흰색 casing.
- M3: `부담 최소경로`, **세그먼트별 경사색 실선**(절대경사 원값, 30% 초과는 `30%+` 구간색) + 흰색 casing.
- 두 경로가 겹쳐도 식별되게 선폭·점선·casing 차등. 색상 외에 선종류·라벨 병행(접근성).
- M3 라벨: 맑음/흐림 `경사 부담 최소경로 (M3, 기상강도 0)`, 비/눈 `경사·기상 부담 최소경로 (M3)`.
- 정류장 마커: 기본 작게, 도착지로 선택되면 강조. 스냅 불가 정류장은 데이터에서 사전 제외.

### 4.5 결과 카드 (순서 고정)

1. **핵심 판정**: `400m 이내 유지` / **`부담 반영 후 400m 초과`(최강조)** / `두 기준 모두 400m 초과`
2. **두 경로 비교**: M0 최단거리, M3 실제 보행거리, M3 거리등가 부담, 우회 `+m`/`+%`,
   동일 경로면 `동일 경로, 비용만 증가`
3. **M3 경로 위 부담 구성**: 실제거리 / 경사 / 기상 / 상호작용 / 합계
4. **스냅 정보**: 출발·도착 스냅거리, `스냅 연결거리는 400m 판정에서 제외` 고지
5. **모델 정보**: 적용 날씨 수치, 계수 4종, `시나리오 파라미터, 실측 보정값 아님`

## 5. 계산 계약

### 5.1 엣지 비용

```text
g = min(abs(grade_percent), 30)
I = max(rain_mm, 0) + 5 × max(snow_cm, 0)
M0 = d
M1 = d × (1 + 0.03 × g)
M2 = M1 × (1 + 0.03 × I)
M3 = M1 × (1 + 0.03 × I + 0.08 × I × g / 100)
```

공식을 복사하지 않고 기존 `CostParameters`·비용함수를 호출하거나, 무작위 표본 일치 테스트를 둔다.

### 5.2 경로 최적화

- M0: `length_m` 합 최소. M3: 선택 날씨의 `cost_m3` 합 최소. 동일한 스냅 O/D 노드 사용.
- 계산 그래프 4개: `m0`, `m3_dry`(맑음·흐림 공유), `m3_rain_2mm`, `m3_snow_1cm`.
- M1/M2 전용 그래프는 만들지 않는다(분해는 선택된 경로 위에서 엣지 단위로 계산).

### 5.3 부담 분해 — 선택된 M3 경로 고정

```text
physical    = Σ M0(edge)          slope       = Σ [M1(edge) − M0(edge)]
weather     = Σ [M2(edge) − M1(edge)]   interaction = Σ [M3(edge) − M2(edge)]
equivalent_m3 = physical + slope + weather + interaction
```

화면 제목은 `선택된 부담 최소경로의 부담 구성`. 연구 전체 평균의 단계별 분해와 혼동 금지.

### 5.4 400m 판정

- M0 판정: M0 경로 네트워크 거리 ≤ 400m. M3 판정: M3 거리등가 부담 ≤ 400m.
- 핵심 재분류: `M0 ≤ 400m < M3`. `M0 > 400m`인데 `M3 ≤ 400m`는 오류로 간주.
- D가 항상 정류장이므로 판정은 모든 요청에서 유의미하다.
- 스냅 연결거리는 표시만 하고 판정에서 제외.

### 5.5 병렬 엣지와 지오메트리

- 입력 행마다 안정적 `edge_id` 부여. 동일 `(u,v)` 병렬 엣지는 프로필별 최저 비용 대표 선택,
  동률은 `cost → length_m → edge_id` 순 tie-break.
- CSR에 프로필별 대표 `edge_id` 보존. 노드열 복원 후 `edge_id` 지오메트리로 연결,
  좌표열 방향 정합(u→v) 처리.

### 6.2 의존성

- Python 선택 의존성: `fastapi`, `uvicorn`, `scipy` (+dev: `httpx`)
- 프론트: `maplibre-gl`, `vite` (React 없음, pmtiles 없음)

### 6.3 베이스맵

- 로컬·저트래픽 데모: OSM 표준 래스터 타일 + `© OpenStreetMap contributors` 상시 표시.
- 공개 확대 시 이용계약 있는 제공자 또는 자체 호스팅으로 교체.

## 7. API 계약

### 7.1 `GET /api/meta`

데이터 버전·생성시각, CRS, 날씨 프리셋, 모델 계수, cap·제외 기준, 출처 문구,
`scenario_parameters_not_calibrated: true`, 공개 안전 데이터 여부.

### 7.2 `POST /api/route`

```json
{
  "origin": {"lng": 126.912379, "lat": 37.455297},
  "destination": {"stop_id": "..."},
  "weather": "rain"
}
```

- origin: 좌표 → 5179 변환 → KD-tree 스냅(100m 초과 시 422).
- destination: `stop_id` → 사전계산된 `stops_snap.parquet`의 노드 (재스냅 없음).
- M0·선택 M3 프로필 Dijkstra → predecessor 복원 → 프로필별 대표 `edge_id` 지오메트리 →
  고정경로 부담 분해 → EPSG:4326 GeoJSON.
- 응답: `request/weather`, `snapping/*`, `m0/*`, `m3/*(segments: grade_abs_percent,
  grade_display_bucket, length_m 포함)`, `breakdown/*`, `comparison/*(path_changed, detour_m,
  detour_percent, threshold_status)`, `warnings`, `metadata/*`.

### 7.3 `GET /api/stops` 또는 정적 `stops.geojson`

정류장 id·이름·종류·좌표. 스냅 실패 정류장은 포함하지 않는다.

### 7.4 `GET /api/health`

그래프 4종 로드 여부, 노드/엣지/정류장 수, 데이터 버전. 계산 없이 즉시 반환.

## 8. 단계별 구현 계획

### 단계 0 — 공개 안전 데이터 기준선 + 노이즈 진단 (게이트)

작업:

1. 혼합 파일에서 OSM 기원 열(`u,v,key,length_m,geometry_wkt`)만 읽고, 노드의
   `elevation_copernicus_m`만으로 방향·절대경사를 재계산한다. Google 열은 산출물에 복사하지 않는다.
2. 결측·100% 초과·비양수 길이·누락 노드를 집계한다. 30% 초과는 원값 보존, 비용에서만 cap.
3. **노이즈 진단**: 엣지 길이 구간별(<20m, 20~50, 50~100, ≥100m) 경사 분포를 비교한다.
   짧은 엣지에서만 경사가 폭증하면 GLO-30 해상도 노이즈로 판정한다.
4. **Google 경사와의 상관·분포 비교**(로컬 검증 용도, 재배포 아님)를 build_report.json에 남긴다.
5. 진단 결과에 따라 완화책(최소 수평길이 기준, 엣지 선형 DEM 다점 샘플링, 길이가중 스무딩)을
   선택·적용하고 적용 전/후를 보고서에 기록한다.
6. **의사결정 게이트**: 보고서를 보고 "발표는 어느 데이터 기준 수치로 가는가"
   (기존 Google 기반 발표 수치 유지 + 웹은 별도 데이터임을 명시 vs Copernicus 기준으로 재계산·정렬)를
   명시적으로 결정한 뒤 단계 2로 넘어간다.

검증: 산출물 컬럼·메타데이터에 `google` 0건 / 유효 엣지 길이 양수·경사 0~100% /
비용용 경사 0~30% / 입력·제외·출력 행수 정합 / OSM·Copernicus 출처 메타데이터 존재.

### 단계 1 — 실행 환경

`pyproject.toml` 선택 의존성(fastapi·uvicorn·scipy), 프론트 `package.json`(maplibre-gl·vite),
`.gitignore`에 `data/processed/prototype/` 확인.
검증: import smoke test, `npm run build`, 기존 86 테스트 통과.

### 단계 2 — 라우팅·지도 산출물

노드 연속 인덱스 매핑(OSM ID 보존), 5179/4326 좌표 배열, 4프로필 비용, 병렬 엣지 대표 선택,
CSR 4종 `.npz`, 경로 복원용 엣지 Parquet, **정류장 스냅 테이블(stop_id→node_idx)·stops.geojson**.
검증: CSR 가중치 유한·비음수 / 프로필별 `(u,v)` 유일 / 대표 edge_id 존재 /
무작위 1,000개 엣지 비용이 `cost_by_model`과 1e-9 이내 일치 / 스냅 실패 정류장 제외 수 기록.

### 단계 3 — M0/M3 경로 엔진

시작 시 일괄 로드, 좌표 스냅(100m), SciPy Dijkstra + predecessor 복원, 지오메트리 방향 정합,
비교·고정경로 분해, 오류 구분(경로 없음/동일 노드/스냅 초과).
검증: 합성 그래프 정확 일치 / 실제망 무작위 OD 100개 NetworkX 대비 1e-6 이내 /
연속 엣지 끝점 간격 허용오차 / 맑음=흐림 / 고정경로에서 `M0 ≤ M1 ≤ M2 ≤ M3` /
`min(M3) ≥ min(M0)` / 분해 합 = 총부담 ±0.01m.

### 단계 4 — FastAPI 계약

`/api/meta`, `/api/route`, `/api/stops`, `/api/health`. 입력 검증(서울 bbox, 날씨 enum,
stop_id 존재). 프론트 빌드·stops.geojson 같은 origin 서빙. 로그에 개인정보 미저장.
검증: 정상·경계·오류 테스트 / 422·404 일관성 / 재시작 후 데이터 버전 일치.

### 단계 5 — 지도 UI·결과 카드

레이아웃, 상태 머신(직전 날씨 결과 보관 포함), 정류장 레이어·선택, M0/M3 겹쳐 그리기,
날씨 자동 재계산, 400m 재분류·우회·분해 표시, 초기화·교환·토글, 오류 상태, 출처·한계 상시 표시.
검증: 1366×768/1920×1080 겹침 없음 / 겹친 경로 식별 / 늦게 도착한 응답이 최신 상태를 덮지 않음 /
키보드 접근성 / 색상 외 구분 수단.

### 단계 6 — 발표용 대표 사례 3개

1. 경사 회피(M0≠건조 M3), 2. 악천후 경로 변화(건조 M3≠눈 M3), 3. 400m 재분류(`M0≤400<M3`).
시드: **시흥5동 (126.912379, 37.455297) → 삼성산자연공원.삼성체육공원 정류장** — 단, 단계 0
데이터로 재검증 후 확정. 선정 기준: 스냅 20m 이하, 지오메트리 연속, 육안 차이, 비용 차 5% 이상,
D는 실제 정류장.
검증: 원클릭 재현 / 데이터 버전 변경 시 사례 검증 스크립트 실패 / 캡처=실측 일치.

### 단계 7 — 성능·회귀·공개 게이트

pytest 전체·프론트 빌드 / OD 100개 벤치마크(warm p95 ≤ 500ms, 2s 초과 0건, cold ≤ 15s,
RSS ≤ 1.5GB) / 첫 상호작용 ≤ 5s / 대표 사례 경로 세그먼트 색 육안 QA / 400m 불변식 /
Google 열·메타 0건 검사 / 출처 표시(`© OpenStreetMap contributors`,
`© European Union, contains modified Copernicus DEM data`) / 베이스맵 정책 /
공개판 수치 vs PPT 수치 차이 검토·정렬.

## 9. 수용 기준 요약

기능: OD 설정(D=정류장), 날씨 4종, M0·M3 동시 표시, 경로 세그먼트 경사색, 분해 합계 일치,
400m 재분류 강조, 스냅 표시·판정 제외 고지, 대표 사례 3개, 초기화·교환·토글.
정확성: 비용식 1,000개 일치, OD 100개 NetworkX 일치, 맑음=흐림, 상호작용 비음수,
`min(M3) ≥ min(M0)`, 병렬 엣지 결정성, GeoJSON 연속성.
성능: warm p95 500ms, cold 15s, RSS 1.5GB, 최신 요청만 반영.
발표·공개: M0/M3 코드에 자연어 라벨 병기, "오르막" 대신 "경사", 시나리오 계수 고지,
Google 파생 0건, 출처 상시 표시, 공개판-PPT 수치 정합 설명.

## 11. 구현 순서와 중단 조건

`단계 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7`. 단계 0의 공개 안전 데이터와 의사결정 게이트 통과 전에는
공개용 산출물을 만들지 않는다. 단계 3 정확성 통과 전에는 UI 숫자를 완성 결과로 취급하지 않는다.

## 12. 최종 결정 기록

채택: M0 vs M3 비교 / M3 고정경로 분해 / MapLibre + plain JS + FastAPI + SciPy /
날씨 맑음·흐림 0, 비 2mm, 눈 1cm / 공개판 Copernicus 기반 / 대표 사례 제품 기능화 /

## 13. 첫 작업

첫 커밋은 UI가 아니라 **단계 0**이다. Copernicus 기반 공개 안전 경사망을 생성하고
`build_report.json`으로 Google 기반망과의 차이·노이즈 진단을 수치화한 뒤, 의사결정 게이트를
통과하고 나서 라우팅 엔진과 화면을 만든다.
