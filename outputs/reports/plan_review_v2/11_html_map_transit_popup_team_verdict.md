# HTML 시나리오 지도 보강 팀 검토 결과

## 팀장 독립 판정

HTML 지도는 QGIS 확인을 대체할 수 있는 방향으로 보강되었다. 기존 hidden 취약지역, 시나리오별 부담 감소/해소, S3 경사 개선 구간, 기존 버스·지하철 위치를 같은 화면에서 켜고 끌 수 있다.

중요한 해석: S3의 `hidden 해소`는 0개가 맞지만, `부담 감소`가 0개라는 뜻은 아니다. S3는 45개 hex에서 `delta_vulnerability > 0`이고, 값이 작아 기존 2자리 표시에서 0처럼 보였던 것이다.

## 팀원1 데이터·시각화

- 버스 정류장: `10,664`개
- 지하철역: `303`개
- S3 경사 개선 대상 구간: `2,970`개
- S3 부담 감소 hex: `45`개
- S3 hidden 해소 hex: `0`개

S3 경사 개선 구간은 더 진한 주황색과 굵은 점선으로 조정했다. 버스는 작은 주황 점, 지하철은 더 큰 파란 점으로 구분한다.

## 팀원2 분석 방향

지도 범례는 `부담 감소 hex(해소 아님)`과 `hidden 해소 hex(취약 해제)`를 분리했다. 따라서 “비용이나 취약도 부담이 낮아진 곳”과 “취약 기준선 아래로 실제 해제된 곳”을 혼동하지 않게 했다.

## 팀원3 전처리

정류장 데이터는 `qgis/out_transit_d_candidates.gpkg`의 실제 후보 레이어 `out_transit_d_candidates`를 사용했다. 기본 레이어를 잘못 읽으면 QA outside 레이어가 잡힐 수 있어, 스크립트에서 레이어명을 명시했다.

각 hex에는 가장 가까운 기존 버스 정류장과 지하철역을 centroid 기준으로 붙였다. 이 값은 설명용 직선거리 기준이며, 네트워크 최단경로 비용 자체를 대체하지 않는다.

## 팀원4 모델·팝업

hex 클릭 시 다음 항목이 보인다.

- M0 순수거리, M1 경사반영 비용, M2 기상가산 비용, M3 최종 접근비용
- M3 비용환산 도보시간
- 경사 증가분, 기상 가산분, 경사×기상 상호작용, 총 환경부담
- 가장 가까운 버스/지하철 이름, 직선거리, 67m/분 기준 환산시간
- 기준 취약도, 시나리오 후 취약도, Δ취약도

`Δ취약도`는 6자리까지 표시하도록 바꿔 작은 효과가 0처럼 보이지 않게 했다.

## 팀원5 방법론 검증

`가장 가까운 정류장 거리`는 “왜 취약한가”를 보조 설명하는 값이다. 최종 취약 판정은 여전히 모델의 접근비용과 수요압력 기준에서 나온다. 따라서 팝업의 설명 구조는 정책 검토용으로 타당하지만, 실제 탑승수요 예측으로 해석하면 안 된다.
